API

Keys for programs. Issuers for people.

The API the portal calls, and a program calls with a key. The installer itself does not use a key. It fetches the label URL. The install routes are built and tested, not deployed. The service and platform routes are designed, not built.

Three names

The label host, the API host, and the update host are different names so a build URL cannot be mistaken for the API. The portal is https://build.blunix.io/.

  • Installer. https://{label}.blnx.io/ returns the latest age ciphertext, not cached. https://v{n}.{label}.blnx.io/ returns version n, cached for a year. Otherwise 404. GET and HEAD on / only. No query string. TLS required. Cap 256KiB. No key. The header x-blunix-sha256 is the ciphertext digest. blnx.io is a separate domain, so build files never share cookies with the site, the portal, or the API.
  • API. https://api.blunix.io/v1 is where accounts and publishers write. A Cloudflare Worker, with the same Worker serving the build names.
  • Updates. https://updates.blunix.io/blunix will be the sysupdate manifest generated from the image log. Designed, not built. Releases are on GitHub today, and the log page reads them live.

API keys

A key is for a program, such as the build-proxy. A person keeps using the issuer. A person mints and revokes keys in the portal.

  • Drawn from the OS CSPRNG. Shown once. Stored only as a SHA-256 hash, compared in constant time. A key is high entropy, so it is not stretched the way a password is.
  • Prefix blx_, then 43 base64url characters. Logs may store the hash as a fingerprint. They must not store the key.
  • Scopes. hosts:write is the default: reserve labels and upload builds. hosts:read lists only. Keys are minted, listed, and revoked with a browser session, never with another key. Later scopes, such as log:publish, machines:read, and troubleshoot:request, belong to the service and platform designs.
  • Revocation is immediate. A revoked hash fails closed. Rotation is a new key, then revoke the old one.
  • Header only. Authorization: Bearer. A blx_ token is an account key. A blx_join_ token is a join token for one enrollment, and in this pass it is a 401 everywhere. A JWT is an access token from an allowlisted issuer. A machine call is an Ed25519 signature, not a bearer key. Anything else is a 401. The key is never accepted in a query string.

Sign-in

Authentik at adsas.id is the first issuer. Google and GitHub come later, under the same checks.

  • Allowlist. Authentik at adsas.id, Google, GitHub. The adsas.id discovery URL is recorded at bind time. Google's issuer is https://accounts.google.com. GitHub user login uses that product's OAuth 2.0 authorization-code endpoints.
  • Browser. Authorization code with PKCE (S256), plus state and nonce. Redirect URLs are an exact https match. No wildcard redirect. The session is the cookie __Host-blx_session: Secure, HttpOnly, SameSite=Lax, 12 hours.
  • Cross-site requests. A state-changing call with a session must send x-blunix-csrf: 1 and come from the origin https://build.blunix.io. A call with a bearer key needs neither.
  • Token. Verified against the issuer's JWKS. Issuer, audience, and expiry are checked. The algorithm has to be RS256, ES256, or EdDSA. none is rejected. A failed check is a refusal, including a missing discovery document.
  • No client secret in the tree. The client id, the secret, and the issuer URL are Worker secrets. They do not go in this website.

Routes

JSON in and out, except the ciphertext upload. Errors are fixed strings, {"error":"..."}. The server does not echo a body back, and it does not decrypt.

The install routes in /v1. Built and tested, not deployed.
Call Who Result
GET /v1/health anyone {"ok":true}. No cookie, no auth. CORS allows https://blunix.io to read it, without credentials. This site uses it to say whether the portal is open.
GET /v1/auth/login anyone Redirect to the issuer. The PKCE state is kept on the server for 10 minutes.
GET /v1/auth/callback the issuer Verify, create or find the account, set the session cookie, and return to the portal.
POST /v1/auth/logout session Delete the session.
GET /v1/me session or key The account and its labels. No secrets.
POST /v1/hosts session, or hosts:write Reserve {label}. 201, 409 if taken, 400 if invalid or reserved. 20 labels per account.
GET /v1/hosts session, hosts:read, or hosts:write The account's labels, with the latest version of each.
GET /v1/hosts/{label} owner The label, when it was made, and its versions: number, sha256, size, time.
DELETE /v1/hosts/{label} owner The label and every version stop serving. The name is held 30 days.
POST /v1/hosts/{label}/builds owner The body is raw age ciphertext, application/octet-stream. 201 with the version, sha256, size, and both URLs.
DELETE /v1/hosts/{label}/builds/{n} owner That version stops serving. The latest moves back to the highest remaining version.
POST /v1/keys session only Mint a key with {name, scopes}. The response is the only time the key appears.
GET /v1/keys session only Fingerprints, names, and scopes. Never the key.
DELETE /v1/keys/{fingerprint} session only Revoke that key. Immediate.
  • An upload is age, or it is refused. At most 256KiB. Age binary or age armor. Exactly one stanza in the header, and it is scrypt. A recipient-key stanza, plaintext, YAML, a shell script, and an empty body are 400 {"error":"refused ciphertext"}.
  • Rate limits. 10 label reservations and 30 uploads per account per hour. 60 login starts per address per hour.
  • Audit. A row for each reserve, upload, delete, and key event: time, account, label, version, sha256, key fingerprint. Never a body, a key, or a token.
Designed for later passes, not built.
Call Who Result
GET /v1/log public Rows for a channel. Same record as the log page.
POST /v1/log publisher Append one version, or one withdrawal. An existing version id is refused. Ordinary keys are refused.
PUT /v1/hosts/{label} account Set visibility to public or enrolled.
POST /v1/hosts/{label}/join-tokens account Mint a blx_join_ token. Shown once. Expires. Use cap.
DELETE /v1/join-tokens/{fingerprint} account Revoke that token. Immediate.
POST /v1/machines join token, once Bind an Ed25519 public key to a hostname and a profile.
POST /v1/machines/{hostname}/checkin machine signature Report the document sha256 and the image digest. Return the desired generation.
GET /v1/machines/{hostname}/desired machine signature The same generation, for a machine that woke up.
GET /v1/machines account Inventory. No secrets.
POST /v1/machines/{hostname}/troubleshoots troubleshoot:request Open a collect. A shell scope and a command field are refused.
GET /v1/machines/{hostname}/troubleshoots/{id} troubleshoot:read, or the machine Status. No report body.
DELETE /v1/machines/{hostname}/troubleshoots/{id} troubleshoot:request Cancel. A later result is refused.
POST /v1/machines/{hostname}/troubleshoots/{id}/result machine signature One report, cap 64KiB. Closes the job.
GET /v1/troubleshoots troubleshoot:read Open jobs for the account. No report bodies.

A stolen API key can replace your ciphertext. It cannot produce a document that decrypts under a build key it does not hold. Revoke the API key. The build key is never a field on any of these calls. Machine routes and join tokens are the service contract. Build, deploy, and the collect are the platform contract.
